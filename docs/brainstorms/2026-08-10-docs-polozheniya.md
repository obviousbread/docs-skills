# docs-polozheniya brainstorm

## Context

The local `polozheniya` skill generates complete regulations for organizational units, but its installed copy contains organization-specific data and is not part of the portable `docs-skills` source repository.

The intended product boundary is:

- `docs-polozheniya` creates a standalone HR document with its own approval block, seven sections, sign-off table, and acquaintance sheet.
- `docs-di` creates employee job descriptions and can use a unit regulation as a source.
- `docs-ord` creates orders, directives, and instructions with an organizational header, preamble, and directive section. It does not own standalone unit regulations.

## Decision

Add a self-contained `skills/docs-polozheniya` skill that:

- reads organization and leader details from `~/.docs-plugin/org_details.md`;
- contains no real personal or organizational data;
- supports department and directorate regulations;
- preserves the complete standalone document shape;
- validates required inputs and avoids overwriting files;
- includes focused tests and quality references;
- is discoverable through the existing Vercel Skills distribution.

Extend `docs-init` with the grammatical forms and output directory needed by the new generator. Clarify routing in `docs-di` and `docs-ord`.

## Alternatives rejected

- Keeping the skill only in `WORK/.agents`: installed copies are not the release source.
- Making regulations an attachment generated by `docs-ord`: this contradicts the standalone document format.
- Adding a shared runtime package: every skill must remain independently installable.
- Adding support for every possible unit type now: department and directorate cover the validated source behavior.

## Release intent

Ship as version `0.6.0` because this adds a new public skill and configuration surface.

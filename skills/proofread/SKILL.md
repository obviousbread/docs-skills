# Вычитка DOCX с отслеживаемыми правками

Оставлять исходный файл неизменным. Создавать рядом отдельную копию
`<имя> (с правками).docx`.

Использовать готовый движок `scripts/redline_docx.py`; не собирать OOXML
временными скриптами. Он сохраняет форматирование, изображения и таблицы,
работает с текстом внутри гиперссылок, включает отслеживание изменений,
исправляет одинаковые копии абзаца и добавляет нативные комментарии Word.

## Рабочий процесс

1. Для рабочего документа сначала получить релевантную терминологию из
   `WorkVault/2.Wiki/`, затем при необходимости открыть оригиналы из карточек.

2. Извлечь текст одним вызовом:

   ```bash
   python3 .agents/skills/proofread/scripts/redline_docx.py extract "ВХОД.docx"
   ```

   Номер `[N]` — адрес абзаца или ячейки. Повторяющийся одинаковый текст в
   выводе показывается один раз, но `review` по умолчанию исправляет все его
   копии. Маркер `⟨SHY⟩` означает мягкий перенос в исходном OOXML и не является
   частью текста для `old`.

3. Найти явные ошибки: опечатки, согласование, управление, пунктуацию,
   регистр, кавычки, тире, нумерацию, единообразие сокращений и неудачные
   канцелярские конструкции. Смысловые и числовые изменения вносить только
   при достаточном основании.

   Не считать визуально слитные слова ошибкой автоматически. Сначала проверить
   маркер `⟨SHY⟩` в выводе `extract`:

   - если между частями уже стоит мягкий перенос, считать его намеренным по
     умолчанию и не добавлять пробел, пока контекст явно не доказывает ошибку;
   - если мягкого переноса нет, а два самостоятельных слова действительно
     записаны слитно, считать это вероятной опечаткой и исправлять;
   - не удалять мягкие переносы при общей типографической нормализации.

4. Создать `edits.json` вне папки скилла:

   ```json
   {
     "author": "Корректор",
     "edits": [
       {
         "block": 12,
         "old": "текст с ошибкой",
         "new": "исправленный текст",
         "comment": "Формулировка допускает два прочтения; выбран вариант, согласованный с контекстом."
       }
     ]
   }
   ```

   Использовать точный `old`. Для удаления указать пустой `new`. Поле
   `comment` необязательно. Добавлять его только там, где читателю действительно
   нужно объяснение: при неоднозначности, смысловом или фактическом уточнении,
   неочевидном выборе нормы либо спорной стилистической правке. Не добавлять
   комментарии к пробелам, знакам препинания, регистру, кавычкам, тире,
   очевидным опечаткам и другим механическим исправлениям. Для правки только
   выбранного абзаца при наличии одинаковых копий добавить
   `"all_duplicates": false`; в остальных случаях оставлять значение по
   умолчанию `true`. Не допускать пересекающихся правок в одном абзаце.

5. Выполнить preflight и устранить все `NOT FOUND`, `AMBIGUOUS`, `overlaps`,
   `old == new`:

   ```bash
   python3 .agents/skills/proofread/scripts/redline_docx.py check "ВХОД.docx" --edits edits.json
   ```

6. Применить режим рецензирования:

   ```bash
   python3 .agents/skills/proofread/scripts/redline_docx.py review "ВХОД.docx" "ВЫХОД.docx" --edits edits.json
   ```

   `review` всегда создаёт tracked changes и выделяет их жёлтым. Нативный
   комментарий Word создаётся только для правки с непустым полем `comment`.
   `apply` оставлен для совместимости и создаёт обычные tracked changes без
   жёлтого выделения и комментариев.

7. Проверить структуру:

   ```bash
   python3 .agents/skills/proofread/scripts/redline_docx.py audit "ВЫХОД.docx"
   ```

   Принимать файл только если `zip_ok=True`, `track_changes=True`, число
   `revision_runs` равно `yellow_runs`, а количества комментариев и трёх видов
   якорей совпадают. Нулевое количество комментариев допустимо.

8. Использовать skill `documents` для финального render → PNG. Просмотреть
   каждую страницу при 100 %. После любой последующей OOXML-правки повторить
   render. Проверить отсутствие обрезки, наложений, повреждённых таблиц,
   пропавших символов, смещения колонтитулов и изменения числа страниц.

9. Вернуть только итоговый DOCX. Кратко указать число содержательных
   комментариев, включая ноль, и факт постраничной проверки. Не отдавать
   `edits.json`, PDF и PNG без запроса.

## Типографика русского текста

- Использовать неразрывный пробел между инициалами и фамилией, в сокращениях
  `т. д.`, `т. п.`, перед единицами и знаком процента.
- Использовать тире `–` в диапазонах и конструкциях с тире; дефис оставлять в
  сложных словах.
- Использовать русские кавычки `«...»`, внутри — `„...“`.
- Не менять `е` на `ё` выборочно: соблюдать единый стиль документа.
- Не нормализовать всё форматирование документа без прямой просьбы.
